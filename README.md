# dsh-cn-nav · ds概念版

给 DeepSeek Harness 的 Web 界面加一条**底部导航栏**（首页 / AI助手 / 短视频 / 个人）、
一个首页信息流、一个蓝白个人中心，以及开屏 / 弹窗 / 横幅三类广告。

第三方开源娱乐插件。纯客户端，零第三方依赖，不写 `document.body`，不改官方 UI，
图标和控件全部手绘。

---

## 五个部件

导航栏四格：**首页 / AI助手 / 短视频 / 个人**。开机（每次页面加载）自动落到首页。

| 部件 | 落位 | 行为 |
|---|---|---|
| 底部导航栏 | `shell.bottom` | 官方语义是「三栏之下的全宽底部内容，其渲染高度会压缩三栏可用高度」，所以它出现时输入框等原有内容**整体上移**，不是浮层遮挡。四格均分 + 滑动药丸。 |
| 首页 | `main` 面板 `cn-home` | 欢迎卡 + **官方公告（自动同步）** + 直达最近会话的窗口。详见下节。 |
| AI助手 | 官方 `conversation` 面板 | 就是原来的会话面板，标签改名为「AI助手」。 |
| 短视频 | `main` 面板 `cn-shortvideo` | 内嵌 `https://www.bilibili.com/`（实测 B 站不禁止 iframe）。带刷新与「在浏览器打开」。 |
| 个人中心 | `main` 面板 `cn-profile` | 蓝白配色的「我的」页：余额、今日已用、近 7 天柱状图、数据来源、关于。**不跳转任何官网**。 |
| 开屏广告 | 渲染在 `shell.bottom` 内部 | 全屏浮层（`position:fixed`，视觉上满屏）。按 `cadence` 出现，默认每次启动一次、刷新不重复。 |
| 弹窗广告 | 渲染在 `shell.bottom` 内部 | 每次进入 AI助手 有 25% 概率弹出居中卡片，关闭按钮在卡片下方独立一个。 |
| 会话结束横幅 | 渲染在 `shell.bottom` 内部 | 每轮对话结束后按概率在顶部弹一条细横幅，12 秒自动收起、可手动关；**不挡操作、不推挤内容**。 |

```
├─────────────────────────────────────┤
│ 会话                      [新建会话] │
│  某个会话标题               5 分钟前 ⌃│
│  另一个会话                   昨天   ▮│
│  DeepSeek Harness        广告创意   ▮│

├─────────────────────────────────────┤

│ [▦ 插件]        [◷ 自动化任务]       │
└─────────────────────────────────────┘
```

**整页纵向滚动**：首页控件多，所以面板本身就是滚动容器
（`.cnn-panel--scroll` = 定高 + `overflow-y:auto` + `overscroll-behavior:contain`，配 8px 细滚动条）。
内容用 `min-height:100%`，内容不足一屏时也会铺满背景，不会露出空白条。
短视频面板**不走**这条（保持 flex，让 iframe 精确填满）。

**会话列表再套一层自己的竖向滚动**：行样式保持原样（左标题、右时间），
外面包一个 `.cnn-sessionscroll` —— `max-height:216px` + `overflow-y:auto`，
右侧一条 8px 细滚动条（悬停加深）。列表项多到超过五行为止才出现滚动条，
少的时候和普通列表没区别。

**广告伪装成会话行**：广告行和会话行用的是**同一套 `.cnn-sessions__item` 样式**，
混排在列表里 —— 每 3 条会话后插一条，只有右侧那个 8.5px / 38% 透明度 / 细边框的
「广告创意」是唯一的破绽。文案与跳转在 `HOME_ADS` 里改：

```js
const HOME_ADS = [
  { id: 'dsh-harness', kind: 'dsh',      title: '…', desc: '…', url: '…' },
  { id: 'api-topup',   kind: 'recharge', title: '…', desc: '…', url: '…' }
]
```

> 广告卡只显示 `title`（这样才像会话标题），`desc` 放在 `title` 属性里做悬停提示。
> **API 充值类广告不要写具体金额或单价** —— 官方政策会变，写死就是迟早过期的数字。

**快捷入口**两个方框直接跳到宿主自己的 `plugins` / `schedules` 面板（`selectPanel`），
所以点进去之后底部导航**不再高亮任何一格**——为此加了 `external` 这个中间态：
它被快捷入口置位、被任意本插件面板的挂载清掉，底部指示器在该状态下隐藏。

**公告**由 Host 半侧抓 `https://www.deepseek.com/news` 并解析（标题 / 日期 / 摘要 / 链接），
缓存 10 分钟；点条目在新标签页打开原文；「刷新」带 `?force=1` 绕过缓存。
解析失败时会附上具体错误信息，不影响其他部分。

### 顶部公告条

首页最上面那几条蓝底白字的是公告条，和下面的文章列表不是一回事：

| 来源 | 内容 | 能否抓 |
|---|---|---|
| `https://www.deepseek.com/` **首页底部** | 模型版本更新那类（带 sparkle 小图标） | ✅ **自动同步** |
| 平台鉴权推送 | 计费变更这类 | ❌ 走本地配置 |

自动同步的做法：Host 抓首页 HTML，取**内含 `ds-sparkle-image` 图标的那个 `<a>`**，
剥掉标签就是公告全文，链接用它自己的 `href`。实测抓到：

```
DeepSeek V4.1 Flash 现已更新至 V4.1-Flash-1017 版本，项目开发能力提升显著，
更低成本、更快速度完成任务；新增 API 支持网页搜索与抓取，欢迎测试和反馈
→ https://api-docs.deepseek.com/zh-cn/guides/search/
```

缓存 10 分钟；点「刷新」带 `?force=1` 一起强制重拉。抓不到时回退到上一次成功的结果。

`platform.deepseek.com/api/v0/*` 下试过 16 个候选路径（announcements / notices /
messages / banners …）**全部 404**，所以那类平台推送的公告仍然只能手填。

其余公告由本地数组提供，直接改就能增删：

```js
const NOTICES = [
  { id: 'api-search-fetch-billing', text: '…', url: '', dismissible: true }
]
```

- `url` 为空就不显示「点击查看详情」
- `×` 点掉后写入 `localStorage['dsh-cn-nav:notice:<id>'] = '1'`，想让它回来就清掉
- 将来如果能拿到平台的公告接口（需要 `deepseekAccount.getPlatformSession()` 的 token），
  我可以把它接到 `/dsh-cn-nav/notices` 做真自动同步

**会话窗口**订阅宿主的 `sessions.list`（`ObservableSnapshot<SessionListState>`，
即 `ids + byId`），按更新时间倒序取前 8 条；点击走 `uiWorkspace.openSession(sessionId)`
直接跳进那个会话。列表为空时显示空态。

**开机进首页**：`shell.bottom` 挂载后 700ms 试一次 `selectPanel('cn-home')`，
失败（layout 还没就绪）每 400ms 重试，最多 6 次；你一旦点过任何 Tab 就不再抢。
这是模块级一次性标志，刷新页面才会重置。

### 为什么个人页不能内嵌

`platform.deepseek.com` 返回 `Content-Security-Policy: frame-ancestors 'none';`，
浏览器会拒绝把它放进 iframe。这是对方的安全策略，绕不过去，所以只能新标签页打开。

### 数据从哪来（自己取，不依赖桌宠）

和 `dsh-whale-widget` 用的是**同一套取数方式**，但完全独立 —— 不读它的任何文件，
它装不装、开不开都不影响本插件：

1. `ctx.credentials.resolve('DEEPSEEK_API_KEY')` 拿 API key
2. `GET https://api.deepseek.com/user/balance`（`Authorization: Bearer`）
3. 每次观测写进自己的账本 `$DSH_HOME/.dsh-cn-nav-usage.json`

「今日已用 / 近 7 天」是**余额差分**：相邻两次观测之间余额下降多少算消费，上涨算充值，
所以充值不会被算成负消费。金额用整数单位 `1e8` 记账避免浮点漂移，只保留最近 60 天。

| 显示项 | 来源 |
|---|---|
| 账户余额 | 最后一次观测的 `total_balance` |
| 今日已用 | 当日 `debitUnits / 1e8` |
| 今日充值 | 当日 `creditUnits / 1e8` |
| 近 7 天 | 逐日 `debitUnits`，柱状图 + 合计 |

观测时机：插件启动后 3 秒一次，之后每 5 分钟；打开个人页时若距上次观测超过 45 秒会补一次，
点「立即刷新」走 `?force=1`。接口临时失败时返回账本里的旧数据并标 `stale`，
不会把页面清空。

> 实测链路：解析到 `DEEPSEEK_API_KEY` → 余额接口返回 `CNY 12.34` → 写出账本
> `.dsh-cn-nav-usage.json`（opening 12.34）。整条链路上没有任何桌宠文件参与。

**没有 `DEEPSEEK_API_KEY` 时**：页面显示「还没配置 DEEPSEEK_API_KEY，去 DSH 设置里填」，
导航栏、短视频、公告都不受影响。

> **为什么没有「本机模型费用」**：那需要 token 级账目（桌宠是从会话事件按价格表推算的）。
> 本插件只做余额差分，拿不到按模型的拆分，所以那一栏换成了「数据来源」。
> 想要按模型统计，得接会话事件的 usage 字段 + 一张价格表，是另一个量级的活。

### 改法

- 布局与文案：`DICT` 里 `me*` 开头的键
- 身份行：`PROFILE.name` / `PROFILE.version`（头像不再用文字，改为账号头像 / 剪影）
- 功能列表：`PROFILE.rows`（`url` 为空字符串 = 原地展开「关于」）
- 账本路径：`index.js` 的 `candidateFiles()`，默认 `$DSH_HOME/.dshw-usage.json`

## 外观：明暗双套背景

导航栏有**两套**配色，靠根节点上的 `data-cnn-scheme="light|dark"` 切换：

```css
.cnn-bar[data-cnn-scheme="dark"]  { background:#141419; --cnn-fg:#9aa0ab; --cnn-accent:#7b96ff; }
.cnn-bar[data-cnn-scheme="light"] { background:#f4f4f6; --cnn-fg:#6b7280; --cnn-accent:#3358d4; }
```

暗色比页面底色亮一档，亮色比页面底色暗一档 —— 保证它在两种主题下都是**一条能被看见的壳**，
而不是和背景糊成一片。想改配色直接改这两行即可。

明暗**不是猜的**：读 `theme.getTheme().active.colorScheme`，再跟随 `theme/change` 事件更新，
和宿主设置里的外观切换严格同步（包括「跟随系统」时的自动翻转）。

### 自己画的控件

- 三个图标全部手绘 SVG：未选中是描边，选中时同一形状加低透明度填充 → 双色效果
- 选中态用一个自己画的**滑动药丸**（`transform: translateX(index*100%)` + 缓动），不是简单的变色
- 焦点环、`role="tab"` / `aria-selected` / `tabIndex` 都自己管，没有借用宿主任何 UI 原语

## 与开机动画 / 启动屏的兼容（不依赖它们）

本插件**没有任何硬依赖**：`dsh-boot-animation`、`dsh-startup-screen` 一个都没装、
被禁用、或者压根没启动时，全部功能照常可用，导航栏和短视频面板不受任何影响。

开机层存在时，我们**主动等它们**，而不是让它们给我们让路：

```js
window.__DSH_BOOT_ANIM__.el              // 开机视频的根元素
document.getElementById('dsh-startup-root')  // 启动屏的根元素
```

**判断的是「它是否真的显示在屏幕上」**，不是「元素在不在 DOM 里」——
`display:none` / `visibility:hidden` / `opacity:0` / 已脱离文档 的元素一律不算占用。
这一点很关键：那两个插件被禁用时，Host 可能仍然把一个隐藏的壳塞在页面里，
只看存在性会让我们白等 45 秒。

另外还要求**连续 150ms 看不到任何开机层**才放行（只为防开机层比我们晚一步插入，
肉眼看不出延迟）：

| 情形 | 出广告的时机 |
|---|---|
| 两个开机插件都没装 / 都没启用 | **约 0.2 秒**后 |
| 开机视频在演 | 视频结束、根元素被移除之后 |
| 启动屏在演 | 授权序列走完之后 |
| 某个开机层卡死 | 最多 45 秒兜底 |
| 开机层只剩一个隐藏的空壳 | **约 0.2 秒**后（不会白等） |

所以正常顺序是：

```
开机视频 → 启动屏授权序列 → 本插件的开屏广告
```

想接入别的开机类插件，往 `COMPAT.busy()` 里补一条 `COMPAT.visible(el)` 判断即可。

### 为什么广告不挂在 `shell.overlay`

`shell.overlay` 语义上是全屏浮层，但它那一格的生命周期会**跟着主面板走**：
开机跳到首页时挂着它的内容会被卸载，等你切回 AI助手 才重新挂载 —— 表现就是
「广告只在进入 AI助手时才出现」。

所以广告现在渲染在 `BottomNav` 内部（`shell.bottom`），官方明确保证这一格
*"remains mounted across main-panel navigation"*（跨主面板切换保持挂载）。
广告本身是 `position:fixed`，视觉上仍然是满屏浮层。

### 主视觉是内联 SVG，不是图片

**设置 → ds概念版 → 开屏图片链接** 留空时，海报是把 SVG **直接内联进 DOM** 渲染的
（`dangerouslySetInnerHTML`，内容是包内常量）。这样做是因为 `<img src="data:...">`
可能被页面 CSP 的 `img-src` 拦掉，表现就是一片黑底。内联 SVG 不发起图片请求，
没有解码时机，也不受 `img-src` 约束。

只有在设置里填了图片链接才会走 `<img>`。

内置海报的构成：深空蓝渐变 + 细网格 + 同心光环 + 「深度思考」大字 + 幽灵「1M」描边水印；
文案只吹事实层面的东西（百万上下文、深度推理、开源开放），不写任何价格数字。

## 弹窗广告

**只在 AI助手 / 首页这两个界面生效。**

- 切进 AI助手 或 首页 → 掷一次概率
- 切到**短视频 / 个人** → 如果弹窗正开着，**立刻收掉**（不会挡住那两个界面）
- 页面加载后 3 秒内不弹（免得一进来就被挡住）
- 开屏还盖着时不叠第二层

```js
const POPUP = {
  probability: 0.25,   // 25%
  cooldownMs: 0,       // 0 = 每次进入都独立掷；设成毫秒数可限制频率
  clickUrl: ''         // 点广告区域跳转；留空则不跳
}
```

### 广告位上的赞助商

每次弹窗从 `SPONSORS` 里**随机抽一条**，两种版式：

- `variant: 'art'` —— 整张海报（DeepSeek 自己那条）
- `variant: 'brand'` —— 品牌卡片：彩色头图 + 手绘 logo + 品牌名 + 文案

**每个架空品牌有两条创意**（一条逆天、一条克制），随机抽：`copies: [{title, sub}, …]`。

| 品牌 | 品类 | logo | 逆天文案 ／ 克制的文案 |
|---|---|---|---|
| DeepSeek | 官方 | 内联海报 | 事实性表述，不编数字（只有一条） |
| 寻宝 | 网购 | 蓝底白「寻」 | 1 分钱抢整箱手机… ／ 全网好物，一搜就有 |
| 寻宝秒购 | 外卖 | 寻宝 logo + 橙色「秒购」横幅 | 首单 0 元吃大餐… ／ 附近好店，三十分钟送到家 |
| 井刀刀 | 网购 · 低价 | 红底白「井」 | 1 元包邮，9 块 9 抢两件… ／ 天天低价，产地直发 |
| 直直 | 二手手机回收 | 绿底手绘小狗 | 旧手机最高抵 8888 元… ／ 闲置手机，卖个实在价 |
| 慢脚缓慢版 | 看视频赚金币 | 红底手绘相机 | 刷 1 分钟提现 1 元… ／ 刷视频也能攒金币 |
| 豆子 | 短视频 · 记录生活 | 深底金色瓜子 | 发条视频就送 10 万赞… ／ 记录生活的小美好 |

逆天那批是**故意写成的浮夸虚假宣传**，用来戏仿国内 App 广告。为此每个广告位都带一个

## 会员（VIP）

纯本地演示，**没有任何真实支付通道**。会员状态存 `localStorage['dsh-cn-nav:vip']`，
`expiresAt` 过期后自动按普通用户算。

### 档位与免广告范围

| 档位 | 免开屏 | 免弹窗 | 免横幅 | 首页广告位 |
|---|---|---|---|---|
| 普通用户 | ✗ | ✗ | ✗ | ✗ |
| 白银 | ✓ | ✗ | ✗ | ✗ |
| 黄金 | ✓ | ✓ | ✗ | ✗ |
| 钻石 | ✓ | ✓ | ✓ | ✓ |

门禁只有一个函数 `adsBlocked(kind)`，四条广告路径（开屏 / 弹窗 / 横幅 / 首页广告卡）
各自过一遍，不存在漏网的旁路。

### 套餐与价格（虚构）

| | 周卡 | 月卡 | 连续包月 | 季卡 | 连续包季 | 年卡 | 连续包年 |
|---|---|---|---|---|---|---|---|
| 白银 | ¥6 | ¥15 | **¥12** / ¥15 | ¥38 | **¥30** / ¥38 | ¥128 | **¥98** / ¥128 |
| 黄金 | ¥10 | ¥25 | **¥20** / ¥25 | ¥68 | **¥55** / ¥68 | ¥218 | **¥168** / ¥218 |
| 钻石 | ¥16 | ¥40 | **¥32** / ¥40 | ¥108 | **¥88** / ¥108 | ¥348 | **¥268** / ¥348 |

> 加粗的是**首期优惠价**，斜杠后是**次期起的原价** —— 只有首期打折，续费按原价走。
> 续费价不是另写一份数字，而是由 `renewPlan: 'month' | 'quarter' | 'year'` 指向同周期的
> 一次性套餐，**永远等于它的原价**，改价只改一处。套餐按钮上会带一个「首期」小标签，
> 下方说明写「首期 ¥12，次月起 ¥15/月 自动续费，可随时取消」。

连续包月 / 包季 / 包年文案写明「次月起自动续费，可随时取消」。

**协议是九章五十条、2600 字**，塞在一个 96px 高的小滚动框里（约 12 屏）。
「本页价格与支付方式均为虚构、不产生任何真实扣款」这句话被埋在**第四十九条** —— 倒数第二行，
理论上完全披露了，实际上没人会滚到底。

> 协议全文在 `VIP_AGREEMENT` 常量里，改文案不用碰任何逻辑。

### 怎么让它显得值

会员页里塞了四层「诱惑」：

1. **权益墙**：每个档位 6~8 条权益，卡片上只露两条钩子，完整清单在下方用绿色对勾
   铺成两列 —— 满屏的对勾，看着就贵。其中「优先响应」「专属客服」「生日礼包」
   「皮肤会员价」都是编的，反正也没人会用。
2. **划线原价**：连续包月/季/年把原价划掉（`<s>` 灰色删除线），右边才是首期价。
3. **折合每天**：套餐说明下面补一行「折合每天仅 ¥0.67」，把价格拆碎。
4. **从众文案**：权益墙底部一条金色小条「今日已有 12,846 人升级会员」—— 数字写死的。

### 升档补差价

会员记录除了档位与到期时间，还存了 `startedAt` 与 `paid`，所以能算出**剩余价值**：

```
剩余价值 = 已付金额 × (剩余时长 / 总时长)
应付     = 全价 − 剩余价值        （但至少收全价的 35%）
```

规则（自己权衡的）：

- **低档位直接禁选**：会员不能「花钱降级」把更高档位覆盖掉。比当前档位低的档位卡片
  会置灰、标「已是更高档位」，付款按钮同步禁用并提示「当前档位更高，不支持降档购买；
  到期后可重新选择」
- **同档续费** → 全价（相当于续期，不返还差价）
- **升档**（白银 → 黄金 / 钻石）→ 自动抵扣剩余价值，套餐下方会显示
  「升级补差价：原价 ¥X，已按当前会员剩余价值抵扣 ¥Y」
- **35% 保底**：防止「刚买白银立刻升钻石几乎白嫖」

弹窗打开时默认选中**当前档位**（续费视角）；没会员才默认黄金。

`priceFor(tierId, plan)` 一个函数算完；套餐按钮上的价格、付款页顶部的价格、
付款按钮上的价格全部走它，不会出现三处不一致。

> 权益文案也顺手改了：原来那种「弹窗与横幅照旧」的降级腔换成了纯权益描述
> （免开屏 / 启动直达 / 进入不被打断 / 全部广告位免掉）。

### 开屏里的会员钩子

非会员才会看到开屏（白银及以上根本不会出现），所以「跳过」正下方挂了一个金色小药丸：
**「白银会员可跳过 →」**。点它**只叠一个会员弹窗，不会关掉开屏** ——
关开屏就等于白送一次跳过，那这个钩子就成了捷径。

> 真的买成（白银及以上）才会把开屏收掉：这段写在 `setVip()` 里，
> 判 `adsBlocked('splash')` 成立就 `setSplashVisible(false)`，不需要用户再点跳过。
> 会员弹窗层级 1600 > 开屏 1500，所以是「浮在广告上卖会员」，不是「关掉广告」。

### 摇一摇提示

开屏底部居中还可能（`SPLASH.shakeChance`，默认 50%）出现一个**「摇一摇跳转详情页」**：
手绘的手机轮廓 + 两侧动效弧线，图标每 2.6 秒轻微晃一下（`prefers-reduced-motion` 下静止）。

> 按你的要求**只做视觉，不做真实摇动检测**：`pointer-events:none`，点了没反应也不会挡住
> 开屏的点击跳转。概率在每次开屏出现时掷一次，不是每帧重算。

为此会员弹窗从「个人页的局部状态」改成了**常驻在 `shell.bottom` 里的全局弹窗**，
由 `openVipDialog()` / `closeVipDialog()` 控制，任何地方都能拉起。

### 退款通道

会员卡片下方有个「申请退款」小链接（仅会员可见）。规则：

```
可退金额 = 剩余价值 × 50%
剩余价值 = 已付金额 × (剩余时长 / 总时长)
```

退款这条链上有三处故意做得不厚道：

1. **金额全藏**：弹窗里只剩「会员到期」一行，已付金额、剩余价值、可退金额一个都不给你看。
   按钮就叫「确认退款」，没有任何数字。
2. **先斩后奏**：点确认后进入成功页，**过 2 秒**才在下面多出一行很小的红字
   「本次退款已自动扣除服务费，具体金额以实际到账为准」。
3. **退了立刻再卖**：成功页底下多一个「重新开通 · 享专属折扣」，点了直接拉回会员中心
   —— 而此时你已经是普通用户，首充礼包又会跳出来。

> `refundable` 在代码里照算（剩余价值 × 50%），只是从不往界面上送。
> 想让它更狠，可以把成功页那行接上 `{price}`，做成「事后退了多少你才知道」。

### 付款二维码

二维码由 Python 的 `qrcode` 库**预生成**（version 8 / EC-M / 49×49），矩阵以 49 行
0/1 字符串嵌在 `client.js` 里，客户端零依赖、画成一条合并过的 `<path>`。
扫出来的文字是：

> 概念演示：本页价格与收款方式均为虚构，请勿当真。输入 上上下下左右左右ABAB 解锁会员体验。

生成时校验过三个 7×7 定位图案在正确的角上（防导出转置），暗模块占比 50.6%。

### 领取方式

**付款页不给任何提示**，也不留测试按钮 —— 界面上就是一张二维码和一句「请使用…扫描」，
看起来和真的付款页没有区别。

领取的按键序列写在 `client.js` 的 `KONAMI` 常量里。监听的是 `keydown`，
箭头用 `event.key`、字母转成 `KeyA`/`KeyB` 再比对，序列错一位就重置；
只在付款页生效，命中后按所选套餐写入档位与到期时间，进入「开通成功」页。

> 想改序列只改 `KONAMI` 数组；想恢复页面提示，把 `t('vipKonami')` 那一行加回付款页即可。

## 国产特供细节

几个专门为了「像」而做的小东西：

**挽留弹窗** —— 点弹窗的「关闭」有 **85%** 概率不会关（`POPUP.retentionChance`），
而是换成第二个弹窗：「真的要放弃吗？」＋「¥5 无门槛券 · 仅此一次」＋
一个要往下找才看见的「残忍离开」。再点才真关。

> 每次点关闭都**独立掷骰**，没有「一次会话只弹一次」的自我克制 —— 改成 `1` 就是次次都拦。

**永不消的红点** —— 短视频 Tab 上常驻 `99+`，个人 Tab 常驻一个小圆点。
纯 CSS，跟数据无关，永远不会消失。红点带一圈描边，深浅主题下都不糊。

**假限时倒计时** —— 会员中心标题右侧「距优惠结束 00:59」，每秒减一，
**归零自动重置回 00:59**，永远抢不完。

## 改配置

所有可调项集中在 `client.js` 顶部（约第 95 行起）：

```js
const SPLASH = {
  countdownMs: 3000,           // 倒计时；这段时间「跳过」不可用
  firstEntry: true,            // 进入时是否出现
  cadence: 'session',          // 'session' 每次启动一次（默认）| 'always' 每次加载 | 'version' 每版一次
  misclickChance: 0.1,         // 误触诱导概率（点跳过时按钮瞬移到左上角），0 = 关闭
  shakeChance: 0.5,            // 「摇一摇 · 了解更多」提示出现的概率（纯装饰，无摇动检测）
  closeOnEscape: true,         // Esc 是否可关闭
  skipTop: 56,                 // 「跳过」距顶部像素：桌面端标题栏会压住，往下让开
  batchIgnoreThreshold: 3      // 会话切换的批量挂载阈值，见下
}

// 每轮对话结束后的顶部横幅（原来的「会话结束弹整屏开屏」已改成这个）
const TURN_BANNER = {
  probability: 0.5,            // 出现的概率
  durationMs: 12000,           // 停留多久自动收起
  top: 44                      // 距顶部像素（让开窗口标题栏）
}
const BANNER_ADS = [ /* { id, text, url } —— 每次随机抽一条 */ ]
```

> 开屏的主视觉与点击链接**不在代码里改**，去【设置 → ds概念版】改，支持填图片 URL 和跳转链接。

### 换开屏画面

1. **在设置里填图片链接**（推荐）：设置 → ds概念版 → 开屏图片链接。
   注意页面 CSP 可能不允许外域图片，加载失败就是黑底 —— 这也是默认走内联 SVG 的原因。
2. **换成自己做的矢量海报**：替换文件顶部 `PLACEHOLDER_ART_SVG` 里的 SVG 字符串，
   它会**内联进 DOM** 渲染，不走图片加载。

### 调试

地址栏 URL 末尾加 `#cn-splash` 回车，**强制立刻显示一次开屏**，方便改素材（不受节奏限制）。

开屏的出现节奏由 `SPLASH.cadence` 决定：

| 值 | 行为 |
|---|---|
| `session`（默认） | 每次启动一次。`sessionStorage` 跨刷新保留 → F5 不会再弹，关掉重开就恢复 |
| `always` | 每次加载都出（调样式时用，很烦） |
| `version` | 每个插件版本一次（`localStorage`），适合"更新公告"式的开屏 |

### `batchIgnoreThreshold` 是什么

Client 侧没有「一轮对话结束」的事件。本插件挂在 `conversation.chat.turnTail`
（官方语义：*一轮对话完成后的动作行之前*）上，每完成一轮就会挂载一个新实例。

但**切换会话时，历史所有 turn 会一次性成批挂载**。所以用一个 250ms 的合并窗口
统计同批到达的数量：达到阈值（默认 3）就判定为「会话切换」并忽略，否则判定为
「刚完成一轮」。副作用：打开一个只有 1~2 轮历史的会话时，可能被误判成
「完成了一轮」从而触发一次概率判定。只影响观感，不影响正确性。

3. **激活态是反推的** —— 宿主没有「读当前面板」的 API，也没有面板切换事件。
   插件用自己两个面板的挂载状态反推：都没挂载就认为停在会话上。
   因此切到官方的「插件」「定时任务」面板时，底部仍会高亮「会话」。
4. 导航栏固定 56px 高，改 `.cnn-bar` 的 `height` 即可。
